Quickstart

Connect an agent in 5 steps

This walks through the JavaScript SDK. The same flow works over the REST API or the MCP server.

You need: the Platform API running (locally http://127.0.0.1:8787, or your deployed URL), and the VelarumPay wallet app to approve pairing.

1. Install the SDK

npm install @velarumpay/sdk-js

2. Create a client and start pairing

Your agent introduces itself and asks for scopes. The response includes a short code and a pairing URI you can render as a QR for the user to scan.

import { createVelarumPayClient, validatePaymentRequest } from "@velarumpay/sdk-js";

const client = createVelarumPayClient({
  baseUrl: "http://127.0.0.1:8787"   // or your deployed API URL
});

const pairing = await client.createPairingSession({
  agent: {
    agent_id: "agt_local_123",
    agent_name: "Hermes on Alice MacBook",
    runtime: "hermes",
    device_label: "Alice MacBook"
  },
  requested_scopes: [
    "payment.requests.create",
    "payment.requests.read",
    "transaction_contexts.create",
    "transaction_contexts.read"
  ],
  expires_in_seconds: 300
});

// Show pairing.pairing_session.pairing_uri as a QR, or the short code to type.

3. The user approves in their wallet

The person scans the code in the VelarumPay app and approves the scopes. The wallet returns a connection token to your agent. Inject it into the client:

client.setConnectionToken("conn_tok_...");
The connection token is the only credential your agent needs after pairing. Store it securely; treat it like a password scoped to this one user and these scopes.

4. Create a transaction context, then a payment request

The transaction context is the human-readable explanation the user sees before signing. The payment request carries the exact on-chain facts.

await client.createTransactionContext(transactionContextPayload);

const validation = validatePaymentRequest(paymentRequestPayload);
if (!validation.ok) console.error(validation.error);

const created = await client.createPaymentRequest(paymentRequestPayload, {
  idempotencyKey: paymentRequestPayload.idempotency_key
});

5. Read status / poll events

const detail = await client.getPaymentRequest(created.payment_request.request_id);
const events = await client.pollEvents({ since: 0 });

Status moves through pending → signed → broadcasted → confirmed (or failed, expired, rejected). Your agent never signs — it only proposes and reads.

Amounts: a rule that prevents bugs

Always send amounts as exact decimal strings (for example "42.00"), never as floating-point numbers. This avoids rounding errors in money math. See the Protocol page for the full field rules.
